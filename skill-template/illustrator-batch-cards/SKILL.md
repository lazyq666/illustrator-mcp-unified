# Illustrator 批量制卡

将原始模板与角色数据整理为可继续编辑的 Illustrator 卡牌文件。以逐卡内容、图层结构和实际画面均通过检查为完成标准。

## Illustrator 调用规则（强制）

所有 Illustrator 操作，包括读取文档、创建和修改对象、保存、导出及重开验收，只能使用统一版 `illustrator-mcp-server`，工具完整前缀必须是 `mcp__illustrator_mcp_server__`。同名工具不等于同一个服务。

每次调用会操作 Illustrator 的工具前，必须新调用该服务的 `get_runtime_status`，按[版本和后台状态核验](references/script-execution.md#版本和后台状态核验强制)检查版本、后台状态、运行目录及任务占用，不能复用之前的检查结果。核验失败、字段缺失或工具不可用时，立即停止新的 Illustrator 操作，向用户说明原因并等待修复；修复后重新核验。

通用脚本也只能通过该服务的 `run_script` 执行。禁止自动切换其他 MCP、旧 bridge、「电脑」／Computer Use、鼠标键盘模拟或直接脚本执行入口；MCP 故障不构成回退授权。本技能的 `scripts/run_jsx.py` 已停用，不能用它或直接启动执行器绕过 MCP。可以继续不控制 Illustrator 的本地素材整理和日志读取。

## 输入与执行条件

先检查用户消息、附件、指定数据表和模板，汇总已提供的信息，再检查以下输入。这里的「标题」「技能介绍」「图标」均指卡牌上的内容。

| 输入项 | 需要明确的信息 |
| --- | --- |
| 原始模板 | 使用哪个 Illustrator 文件 |
| 角色与制作范围 | 角色编号、名称及本次需要制作哪些卡牌 |
| 标题 | 各卡牌使用的准确标题；标题与角色名称是否为同一字段，以数据或用户说明为准 |
| 技能介绍 | 各卡牌的技能名称与介绍正文；若来自表格，明确对应列 |
| 图标 | 使用哪些图标、素材来源及其与卡牌或技能的对应关系；是否沿用模板图标 |
| 角色图来源位置 | 图片文件、文件夹、附件或可访问链接，以及图片与角色的匹配规则 |
| 名称字稿 | 已准备的矢量 PDF 或由 PDF 导入并验收的 AI 字库；明确整组名称或单字与角色的对应关系，检查缺字 |
| 输出位置 | 最终文件保存目录和命名要求；未指定时可提出具体建议供确认 |

建立逐卡对应表，记录编号、名称、标题、技能介绍、图标、角色图和名称字稿的来源。路径需核实文件是否存在、能否读取；多张候选图片或含义不明的表格列应标为「待确认」。模板中的示例文字和素材不能自动视为本次输入。

### 信息不足时的补充与确认

发现缺失、冲突或对应关系不明时，集中列出已知信息和待补充项，只询问尚未明确的内容。说明暂停生成的具体原因，例如「还缺少技能介绍和角色图来源，暂时无法确定每张卡应使用的内容」。可使用以下形式，并删去已经明确的项目：

> 已找到模板和角色名单，还需要补充或确认：
> - 标题：使用角色名称，还是另一组标题？
> - 技能介绍：请提供正文，或指出数据表中对应的列。
> - 图标：沿用模板图标，还是使用指定素材？如需替换，请说明素材位置与对应关系。
> - 角色图：请提供文件夹路径、附件或链接，并说明图片如何对应角色。

用户补充后，汇总最终的内容与素材对应关系，请用户确认后再开始生成。批量任务可展示对应表供一次确认，无需逐张重复询问。用户已明确确认的项目或已授权的缺失处理规则继续有效；若补充回复已明确确认整份方案并要求开始，直接执行。

等待补充或确认期间，可以检查模板、读取数据和整理素材清单；暂不执行依赖这些输入的卡牌生成或替换。用户未回复不代表同意，不自行编造文案、选用不明图标或替角色指定图片。用户明确要求某项留空、沿用模板、使用占位内容或跳过时，记录该决定即可，不再将其作为缺失项。

完成条件：每张待制作卡牌的必要输入均已确定，或已有用户明确的缺失处理规则；曾经不明确的内容已获得确认。输入原本完整且用户已要求开始时，直接执行，无需额外确认。

执行入口始终遵守上面的强制调用规则。后台执行不抢前台、不使用系统剪贴板。能力不足或需要界面交互时，停止新的 Illustrator 操作，保留已有成果和日志并提示用户；不能为了保存进度而绕过未通过的入口核验。

先做轻量只读探测，再进行批量写入。只有脚本文件而没有执行结果时，交付状态应为「脚本已准备，尚未生成或验收」。统一 MCP 提供 `batch_cards` 与制卡专用工具；先核验当前模板并填写对象对应关系。模板超出专用工具的支持范围时，使用经过小样验证的脚本，不沿用其他模板的固定索引。

面向设计师说明结果。首次提及 ExtendScript 时说明它是 Illustrator 使用的脚本语言；用图层、蒙版、字面和衬边等设计术语解释变更。

## 执行流程

### 1. 创建模板副本并检查第一层图层命名

拿到源文件模板后，先创建工作副本，保留原始文件。打开副本后首先检查卡牌第一层图层的名称是否清楚表达内容用途，再进行后续制作。单卡模板检查文档顶层图层；已有「角色编号 角色名称」父图层时，检查展开该角色后直接显示的一层子图层。更深层的分组、路径、蒙版及对象名称不属于本次命名规范的强制范围。

合格名称应能直接看出图层属于 UI 边框、角色主图、破框叠图、标题、技能文案或背景等哪类内容。已有清晰、准确的名称可以保留；缺少名称，或只有「图层 1」「Layer 2」「复制」等含糊名称时，先查看该层实际内容，再在工作副本中重命名。新名称采用「两位编号 + 内容用途」，例如：

```text
01 UI 边框
02 角色主图
03 技能文案
04 背景
```

示例只说明命名形式，具体类别、数量和编号取自模板实际内容及现有叠放顺序。仅为命名不增删、拆分、合并或重排图层；同层包含多类内容时使用能准确概括的组合名称，不强制每一类单独成层。名称或用途重复时增加实际差异说明，确保同级图层可以区分。

自动修正可判断的名称，无需用户再次批准；只有查看内容后仍无法确定用途时，询问该层含义，不猜测。保留原有可见性和锁定状态，以及图层内的结构、效果和内容。记录「原名称 → 新名称」及对应层级，更新后续脚本中的对象定位依据，避免继续用旧名称查找。

命名检查通过后，读取模板的文字对象、人物裁切结构、画板尺寸、渐变与效果，记录需要替换的对象及其所在层级。更换模板后重新检查命名、定位对象和确认参数，不直接沿用旧模板的固定索引、尺寸或效果设置。

完成条件：卡牌第一层图层均有清晰且符合实际内容的名称；缺失或含糊名称已在副本中修正，每类替换内容均能对应到实际对象。后续复制与验收以这份规范化模板副本为准。

### 2. 检查图片尺寸并确认优化

在批量复制和置入之前读取[图片优化与混合交付](references/image-preparation.md)，对用户已确定的位图读取实际像素宽高。按参考中的源图尺寸规则决定置入方式：大图链接，小图嵌入，并记录到素材对应表。存在长边大于 1600 px 的源图时，列出受影响素材，询问是否开启「等比例缩小至长边 1600 px，并采用无损压缩保存」。没有获得明确同意时不缩小图片；用户拒绝则保留大图原尺寸并继续链接置入。已有明确授权时无需重复询问。

说明印刷精度时结合模板实际尺寸：整幅图片长边置入为 80 mm 时，1600 px 约为 508 PPI。若实际尺寸、裁切放大或印刷要求不同，应按实际有效 PPI 判断；尺寸未知时先读取模板或询问，不直接承诺足够印刷。「无损」只指缩小后的保存压缩，不代表缩小尺寸没有像素损失。

获得同意后，按参考文件生成优化副本，保留原图，检查尺寸、透明度与颜色，再更新角色图对应表。长边小于或等于 1600 px 的图片保留原尺寸，不放大。处理完成或用户明确拒绝优化后，才进入使用这些图片的制作步骤。

### 3. 按角色复制完整结构

优先在同一文档内复制完成命名检查的完整模板。每张卡建立独立画板和独立父图层，父图层使用「角色编号 角色名称」命名。模板各子图层放在角色父图层内，保留规范化后的名称、原有叠放顺序和内容。

```text
56 角色名称
  01 UI 边框
  02 角色主图
  …
57 角色名称
  01 UI 边框
  02 角色主图
  …
```

示例编号与子图层名称仅用于说明层级，实际取自角色数据和模板。每张卡的全部对象应归属于自己的角色父图层；独立画板不能代替正确的图层归属。

### 4. 替换正文与名称

复用模板已有的文字对象，替换正文内容，保留字体和颜色，再根据实际画面调整换行、字号与位置。

按已确认的对应表替换标题、技能名称和介绍正文。图标按确认结果沿用或替换，保留模板中的位置、尺寸和叠放关系；仅在用户要求时调整这些设置。

名称字稿采用「PDF → 导入可编辑路径 → 重建渐变衬边」流程。操作前读取[PDF 字稿导入与渐变衬边](references/pdf-vector-import.md)，使用已准备的矢量 PDF，在 Illustrator 中打开并将实际路径复制到目标图层。已有由 PDF 导入并验收的 AI 字库时，直接复用字形组；无需重复转换 SVG 或逐卡重复导入同一 PDF。PDF 图标等路径素材使用同一导入方式，衬边按其模板要求处理。

先完成名称拼字、等比例缩放和定位，再将字面复制到后方，按当前模板的渐变与偏移路径参数重建独立衬边。字面与衬边分别成组，保留复合路径和镂空；最终名称须能编辑路径节点，不以链接 PDF 或位图替代。完成衬边后再次核对字面镂空。

自动换行和缩字号后仍需检查可读性。文字未溢出只表示容器装得下，不能证明印刷后可读。

### 5. 按图片大小选择链接或嵌入

按素材对应表置入：大图使用外部链接，实现与「文件 → 置入 → 勾选链接」相同的结果；小图直接嵌入 AI，不产生外部图片依赖。仅使用统一 MCP 的图片工具或 `replace_masked_image`，批量脚本中设置相应置入方式。专用工具拒绝的旋转、镜像、倾斜图片，先验证模板专用脚本；无法可靠处理时报告限制，不自动转为界面操作。通过统一 MCP 的图片信息工具核实实际状态，不把所有图片统一设为链接。

保留模板人物的裁切蒙版，只替换蒙版内的图片。按模板的实际画面尺寸和位置设置置入图片，不能因像素尺寸或 PPI 元数据变化而改变画面大小。主图与破框叠图使用同一份源素材和一致的置入方式，并保持相同的缩放与位置，检查是否对齐。使用蒙版裁切；大图的主图和叠图均保留链接，避免破坏性裁图将其意外转成嵌入图。

制作和交付均保留分类结果。按[图片优化与混合交付](references/image-preparation.md)仅将外部链接的大图随 AI 文件交付，核验链接有效；小图保留嵌入状态。

### 6. 顺序批处理并保存

使用 `batch_cards` 提交已确认的计划，并通过 `get_batch_status` 查询进度。它在独立本地进程中执行，按 `chunk_size` 分组生成，每组保存并关闭同一输出文件，下一组重新打开；收到任务编号只表示已接收。其他模板专用脚本只能通过统一 MCP 的 `run_script` 按顺序执行，并获取文档独占权。按实际批量与文件情况分段保存，并记录已生成角色、保存位置和异常。

`ready_for_visual_review` 仅表示重开后的结构检查通过，还须查看每张预览图。完成后清理本次创建的临时对象，另存最终文件。分段保存仅用于恢复，不代表自动断点续跑，也不构成任意数量或文件大小的稳定性承诺。

出现脚本错误、工具调用失败或应用崩溃时，分别记录现象，读取[故障处理与结论边界](references/troubleshooting.md)。中断后先检查已保存成果；需要重做时使用新的模板副本，保留既有结果和日志。同一故障在针对性修正后仍重复出现时，停止重复写入，报告受影响角色与可恢复文件。

### 7. 重开并独立验收

保存后用 `validate_cards` 或新的独立脚本调用重新打开最终文件、获取文档与对象，不沿用保存前的对象引用。验证图片链接时使用任务生成的 `prepared-plan.json`，其中记录了交付目录中的实际路径。逐卡检查以下项目：

| 检查项 | 通过条件 |
| --- | --- |
| 数量与对应关系 | 每个应生成的角色都有对应画板和角色父图层；遗漏及额外内容已处理或说明 |
| 图层命名与归属 | 每个角色父图层包含完整模板子图层；展开角色后第一层图层名称清晰，与规范化模板一致；全部卡牌对象归属正确，原有叠放顺序保留；不要求深层对象逐一重命名 |
| 内容 | 标题、技能名称与介绍、角色名称、图标和人物图逐项匹配已确认输入；留空、沿用或占位内容符合用户决定，替换区域没有误留模板内容 |
| 文字与名称 | 字体、颜色、换行、字号、位置和可读性已检查，字面与衬边效果正确 |
| PDF 字稿与路径素材 | 由矢量 PDF 导入，或复用已验收的 AI 字库，最终为可编辑路径或复合路径；镂空与源字稿一致，透明区域未变为白色填充，无字稿外部链接或位图替代；名称字面与渐变衬边独立，效果与当前模板匹配 |
| 图片优化 | 处理符合用户同意的范围；缩小副本长边为 1600 px，比例、透明度与颜色已检查，原图保留；拒绝优化或原长边不超过 1600 px 的素材未被缩放 |
| 位图与置入方式 | 蒙版结构保留，主图与破框叠图对齐；与素材对应表一致，大图保持链接，小图已嵌入；全部外部引用文件在交付目录中，重开后无缺失或待更新链接 |
| 实际画面 | 每张卡的画面已查看，没有明显遮挡、错位或裁切错误 |

结构检查与视觉检查都要完成。保存成功、文件存在或画板数量正确，均不能单独判定制卡完成。工具无法完成某项检查时，将该项列为未验证。

## 交付

提供 AI 文件及实际外部链接的大图、已完成角色范围、验收结果，以及存在的缺失素材、异常和未验证项；小图已嵌入，无需作为依赖另附。如修正过模板图层命名，提供改名对应记录。报告图片优化是否开启、实际处理数量及链接和嵌入数量；存在外部链接时提示移动或发送需保留整个交付目录。需要恢复时提供最近可用文件与日志位置。明确区分「已保存」「已生成」「已通过验收」。
