# 故障处理与结论边界

本参考整理自用户提供的《Illustrator 批量制卡方法与错误边界》。文中的成功记录来自该指引的既有案例，不代表当前模板或当前运行已经验证。

| 现象 | 处理方法 | 结论边界 |
| --- | --- | --- |
| 各角色被放在公共模板父图层下 | 改为每个角色一个父图层，将完整模板子图层放在角色内部，再逐卡检查归属和叠放顺序 | 原案例生成过层级不合要求的文件；批量生成成功不能证明层级正确 |
| 新建文字框后排版出现问题 | 优先复用模板文字对象，保留字体和颜色后调整排版 | 原案例同期也调整了名称边框实现，不能认定新建文字框是唯一崩溃原因 |
| 跨文档复制复杂卡牌结构不稳定 | 优先在同一文档内复制完整模板；字稿按[PDF 字稿导入流程](pdf-vector-import.md)处理，可复用已验收的 AI 字库 | 单次复制失败不能扩大为所有跨文档复制都不可用；批量前先验证当前入口和目标图层 |
| 字稿导入后镂空丢失或不能编辑路径 | 检查源 PDF 是否包含实际矢量及正确的填充规则；打开 PDF 后复制路径，保留复合路径并对照源字稿核验 | PDF 能打开、素材看起来相似或已嵌入，均不代表可编辑路径与镂空已保留 |
| 找不到对象或渐变 | 检查导入后的实际名称和结构，同时查看模板中的旧名称 | 查找失败不等于对象不存在；导入过程可能改变名称 |
| 对象无法修改或删除 | 检查对象及父级图层的锁定、隐藏状态，确认目标可修改后再操作 | 避免仅凭操作失败判定对象损坏 |
| 重开后对象读取报错，例如 `MRAP` | 在独立调用中重新获取文档与对象，再执行核验 | 原案例按此处理后核验通过，具体错误原因尚未证实 |
| 怀疑图片过大导致崩溃 | 保留错误记录和最近保存成果，检查实际失败阶段；分段保存以便恢复 | 没有证据确认内存耗尽是根因，不能承诺任意文件大小或卡牌数量都稳定 |
| 大图制卡打开或编辑缓慢 | 按[图片优化与混合交付](image-preparation.md)检查长边，征得同意后缩小并无损压缩；大图链接，小图嵌入 | 性能优化不等于已确认崩溃原因，实际改善程度需以当前文件验证 |
| 重开后图片链接缺失 | 检查交付目录中的 `Links/` 素材是否齐全，将引用重新指向对应文件后保存、重开 | 交付必须包含 AI 与链接素材，仅有 AI 文件不足以完成链接式交付 |
| 中文乱码或脚本接口不兼容 | 检查脚本传输编码和 ExtendScript 支持范围；必要时转义中文，使用兼容语法和数据解析方式 | 以实际执行结果验证兼容性，不假设现代 JavaScript 写法都受支持 |
| 保存成功但内容还是模板内容 | 对照角色对应表逐卡核对正文、名称、图片和排版 | 文件存在、画板数量正确均不足以证明替换成功 |

恢复时先确定问题发生在脚本执行、工具调用还是应用本身，并分别记录错误与时间、受影响角色、最近保存路径。先检查已保存文件的实际内容，再决定是否继续。需要重做时从新的模板副本开始，保留已有成果和日志。

## 本机后台执行补充

- 读取叠放顺序时，本机 30.2.1 的部分正常路径会在 `zOrderPosition` 抛出内部错误；统一制卡工具使用已实测的 `absoluteZOrderPosition`，并保留回归测试。
- 即使显式指定图片的父组，置入文件仍可能检查文档当前图层。统一工具在目标层解锁期间临时选中它，结束后恢复层状态；这不激活应用窗口。
- `BACKGROUND_UNSUPPORTED`、`ILLUSTRATOR_BUSY_OR_UNCONFIRMED` 不触发 Computer Use。保留任务编号和日志，核对运行状态后再处理。
